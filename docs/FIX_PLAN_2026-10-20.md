# Fix Plan — from FUNCTIONAL_AUDIT_2026-10-20

Principles: security before features; every DB change is a numbered migration file in `supabase/migrations/` **and** applied to the live project; each change is verified (SQL role simulation, `tsc`, lint) before moving on; nothing deleted that has data without being asked.

## Phase 1 — Database security and plumbing (migrations)
| ID | Change | Verify |
|----|--------|--------|
| D1 | Add `broker` to `user_role` (the broker portal gate checks `role === 'broker'`, a value that never existed, so nobody could ever log in as a broker) | enum lists it |
| D2 | `current_user_is_staff()` helper (active profile, role in admin/manager/sales_advisor/telecaller; **not** broker) | callable, returns false for unknown uid |
| D3 | `handle_new_user()` reads `raw_app_meta_data.role = 'broker'` (service-only field) so broker accounts never start as `sales_advisor` | trigger def |
| D4 | RLS rewrite: every `USING true` / `WITH CHECK true` write policy on an authenticated role replaced. Money/HR/config tables = `admin`/`manager` (payroll adds own-slip read); operational tables = staff. Reads on `audit_logs`, `whatsapp_messages`, `automation_logs`, `meta_lead_webhook_events` = staff | role-simulated SQL: manager allowed, telecaller denied on payroll, unknown/broker uid denied everywhere |
| D5 | Drop anon `ALL` on `chatbot_sessions` and anon read on `auto_reply_rules` (code uses the service client) | policy list |
| D6 | `pg_cron` + hourly `release_expired_holds()` (fixes #2 with no new HTTP secret) | `cron.job` row, manual run |
