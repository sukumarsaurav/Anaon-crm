# Fix Plan 2 — everything still open after the UI walk-through

Order: data integrity → correctness → UX polish → verification. Each item ships with a test (Vitest, or `tests/sql`) and, for schema changes, a migration applied to the live project.

## A. Correctness and data integrity
| ID | Item | Approach |
|----|------|----------|
| A1 | SLA clock runs from lead creation, so every "contacted" lead looks breached | New `leads.stage_changed_at` (trigger + backfill from the last stage-change activity); `computeSlaStatus` uses it |
| A2 | "Budget matches inventory" scoring can never apply | Central `rescoreLead()` that loads the project's price range from its plots and every scoring path uses it |
| A3 | Automation `score` condition never matches | Engine loads the lead's score when a condition needs it |
| A4 | Booking numbers are random (collision = failed insert) | Sequence-based default `BKG-<year>-NNN` |
| A5 | Duplicate WhatsApp template names | Rename the two draft duplicates, unique `(name, language)`, friendly error on create |
| A6 | Two campaigns share one `utm_campaign` | Fix the data, unique index, validation in `createCampaign` |
| A7 | Marketing headline ROAS counts unattributed revenue | Headline uses attributed revenue only (same basis as the tables) |
| A8 | Approved **unpaid** leave is not deducted in payroll | Slip generation counts approved unpaid-leave days in the month as LOP |
| A9 | Deactivated staff keep a working session | Dashboard layout signs out inactive profiles |
| A10 | Sessions list grows forever (21 and counting) | Daily `pg_cron` purge of sessions older than 30 days; the page shows only recent ones |
